# Design Decisions

Short log of deliberate choices. One line each, newest first.

- **DD-033** (2026-06-20) — **Coverage line CLOSED (no measurable gain) + the deltas we chased were a JUDGE ARTIFACT.** Third and final attack on decomposition/completeness: an **in-loop full-text coverage gate** — before honoring `finish`, re-judge completeness against the FULL evidence text (the generator's view) via `prompts/agent_coverage.md`, and if parts are unsupported, redirect the controller to search them (capped `GATE_MAX_REDIRECTS=2`, never on the last round). Built to fix the diagnosed flaw in the prior **adaptive-coverage** attempt (the controller self-reported `open` from 300-char *router-view snippets* it can't judge coverage from — proven noise: questions ending with `open>0` scored *higher* than those that closed it, and a18 finished with all 3 parts flagged open yet fully correct). First run looked like a **big win: corr 0.680→0.840 (+0.16)**. **It was not real.** The faithfulness judge (groq `llama-4-scout`) had **degenerated to all-PARTIAL (faith=0.000)** that run — caught via an a01 control (semantically identical answer + identical context that an earlier run scored SUPPORTED). Switched judge to **`gemini-2.5-flash-lite`** and re-graded *the same stored answers* (rebuilding each generator's exact context from the chunk store, `scripts/regrade.py`): the gate's **0.840 collapsed to 0.520** — a **0.32 swing on byte-identical answers**. Under the trustworthy judge **B1 0.56 ≈ adaptive 0.55 ≈ gate 0.58** correctness and **~0.80–0.82 faithfulness all three** — statistically indistinguishable, with gate's own two samples spanning 0.52→0.64 (run-to-run ±0.12). **Verdict:** all three coverage mechanisms (DD-032 blind planner → adaptive → this gate) **fail to beat plain B1 once measured on a trustworthy gauge**; the gate costs +1 full-text call/finish + extra rounds for nothing → **removed entirely** (config flag, gate code in `loop.py`, `prompts/agent_coverage.md`, and the now-dead `initial_open`/`open_at_finish` trajectory meters — same "earned no place, don't keep dead code" stance as DD-032). General principle (the real lesson, transferable): **a fluent wrong *measurement* looks like a real result.** Our noise floor — judge-choice ±0.32 on identical answers, run-to-run ±0.12 — *dwarfs* the effects we'd been acting on (adaptive's "−0.08 faith", this gate's "+0.16 corr" were all within or caused by it). **You cannot detect a 0.05 effect with a 0.1–0.3 noise instrument.** `gemini-2.5-flash-lite` is the better judge (catches INCORRECT — 4 vs llama's 0 — and gives a real faith distribution, not degenerate all-PARTIAL); caveat: same family as controller/generator (mild self-grade, accepted). **Next: re-establish the baseline under the current combo (controller/generator `gemini-2.5-flash`, judge `gemini-2.5-flash-lite`) at n≥3 and report mean *and spread* — the spread is the bar every future change must clear.**
- **DD-032** (2026-06-20) — **Completeness gate (B) on top of plan-first decomposition (A) — A/B'd, REMOVED (gate never fired).** Built explicit query decomposition (A: a planner call breaks the question into atomic sub-questions, shown to the controller, `prompts/agent_decompose.md`) and a completeness gate (B: at `finish`, a self-check call vetoes stopping while a planned sub-question is still uncovered). Ran A-alone vs A+B on v2 (n=1 each). **The gate vetoed 0 finishes across all 25 questions** — `gate_vetoes=0` everywhere. Mechanism: the *advisory* plan (A) already makes the controller cover its sub-questions before it chooses `finish`, so the *enforced* gate never had anything to veto; and the multi-part questions that still fail don't reach a gated finish anyway — they exit `budget`/`oscillation` (e.g. a16 synthesis-drop), miss an **un-asked** fact (a24's superseded Azure variant isn't a planned sub-question), or need **breadth enumeration** (a05/a21, fuzzy "covered"). So the gate cost ~+7 controller calls / ~+8K tokens per run for **zero behavioral change**. Because it was inert, A+B was behaviorally ≡ A; the A+B run's lower headline (0.571 vs A's 0.714) was pure temp-0 run-to-run variance, not the gate. **Removed entirely** (code + `prompts/agent_coverage.md` + `agent.completeness_gate` config + `gate_vetoes` trajectory field), not just config-gated — it earned no place. General principle (transferable, cf. DD-026 masked-component): **when a lighter advisory mechanism already produces the behavior, a heavier enforcement layer on top is pure overhead — measure the cheap version first and only add enforcement if the advisory version visibly fails.** Decomposition (A) KEPT but still under measurement — at n=2 it's **flat on correctness** (A mean 0.643 == B1 mean 0.643) with **marginally higher faith** (0.944 vs 0.930) and a mixed per-question story (may help a14/a17, flaky a16/a12, may *hurt* a03 via over-decomposition, `plan_size=4`); needs more A-only runs to call. `plan_size` retained in the trajectory as the decomposition meter.
- **DD-031** (2026-06-20) — **Action space trimmed to `[search, list_sources, finish]` — both `expand_*` dropped (lean menu WON).** On v2 (B0 full-menu n=3 vs B1 lean n=2): adding `expand_around_chunk` robustly regressed 5 v1-solid Qs (a02/a05/a10 3/3→0/3; a12/a17 degraded) while never firing reliably (a18: 0/0/1 calls) nor fixing its target (a16: 0/3); `expand_document` was dead weight (0 calls on all 3 of its breadth meters a05/a06/a12). Dropping both: correctness **0.587→0.643**, faithfulness **0.829→0.930** (cleanest signal — fewer distractor tools = less controller wandering = more grounded answers). Principle (transferable): **the action space isn't free — every tool taxes routing on EVERY question** (bigger prompt = noisier selection), so a tool must be *measurably net-positive*, not "might be useful." Both kept in `agent/tools.py` but config-gated OFF; re-enable only behind a properly-prompted A/B. Caveats: lean run n=2; a05 did **not** recover (genuine coverage failure, next lever). New baseline = **B1 lean, 0.643 / faith 0.930** on v2 (25 Qs). Failures are **faithful-but-incomplete** (0 hallucinations, failing Qs grade SUPPORTED) → binding constraint is **decomposition/completeness**, not grounding.
- **DD-030** (2026-06-20) — **Controller router view is a PREFIX snippet — fix DEFERRED.** The controller sees each chunk truncated to its first `CONTROLLER_SNIPPET_CHARS=300` chars (`loop.py:router_view`), so a fact in a chunk's latter half is invisible to the *routing* model. Acceptable because the split is two-model: the **generator** writes from FULL `hit.text` (`answer.py`, no trim at `answer_char_budget=0`), so a tail fact is lost only to the controller's view — impact is routing inefficiency (over-search) + a narrowly-missed clue in *chained* multi-hop. Fixes if it bites (cheap→principled): (a) raise the cap; (b) **relevance-centered snippet** — show the query-matching span instead of the prefix (query-biased summarization; ~20-line lexical hand-roll); (c) a `read_chunk` tool returning full text on demand. **Deferred (YAGNI):** no failure yet traces to controller-blindness; revisit if a run finishes/mis-routes *despite* holding the answer-bearing chunk.
- **DD-029** (2026-06-20) — **Stop-condition redesign (oscillation guard: hard-break → patience + feedback + abstention guard) — WON, baseline 0.917.** The DD-028 audit found the guard firing on a **single** redundant retrieval: `oscillation` exits scored 68% vs `finish` 82%, cutting multi-hop off mid-investigation. Principle: **stop on GLOBAL stuckness, not a LOCAL stumble** — one redundant query means *reformulate*, not *abort*. Changes (`loop.py` + `prompts/agent_react.md`): (1) **patience** — `OSCILLATION_PATIENCE=2`, trip only on 2 *consecutive* redundant rounds, reset on progress (`max_rounds` = hard backstop); (2) **feedback** — annotate the redundant round with `[NOTE: NO NEW EVIDENCE FOUND]` (patience is inert at temp 0 without it); (3) prompt pointer; (4) **abstention guard** — patience first regressed a08 (told grounded-stopping Qs to keep searching → answered a distractor), fixed with a bullet: "if focused searches keep missing the fact, finish with 'Not enough information.'" Results (3 runs): correctness **0.917** (14–15/16), 14/16 robust 3/3, abstention 3/3, `oscillation` exits→0; controller ~94K tok (patience tax). Remaining flaky: **a16** (synthesis-incompleteness), **a07** (judge-borderline). Supersedes DD-028's 0.615. Writeup: `docs/agents/AGENT_LOOP_STOP_CONDITIONS.md`.
- **DD-028** (2026-06-19) — **First AGENTIC baseline — the new-lineage anchor.** Config: 4 tools `[search, expand_document, list_sources, finish]`, `max_rounds=5`, `answer_char_budget=0`, **`parent_expansion` OFF** (the controller can expand on demand, so fixed ±1-neighbour auto-expansion just inflates context). Corpus grew to **22 docs** (added a 7-doc workers'-comp ETL domain) — first two-domain baseline. Eval = `agentic.yaml` (16 Qs). **Results: correctness 8/13=0.615, abstention 3/3, trajectory 9/16=0.562.** Cost: controller 78K tok / 55 calls, ~3.3 rounds/Q. Findings: (1) **decomposition completeness is the binding constraint** (1/4) — the agent takes the hops (trajectory 4/4) but the generator drops 2nd-hop facts in synthesis; (2) **special tools under-used** (`expand_document` 2×, `list_sources` 1× across 16 Qs) — behaves ~like `[search,finish]`; (3) grounded_stopping's `expects_exit: finish` is too strict — abstentions were correct but reached via the oscillation guard (the 0/3 trajectory is an assertion artifact). Anchor every future agentic A/B compares against.
- **DD-027** (2026-06-19) — **Agentic eval cases bind trajectory to raw tool *names*, deliberately.** `trajectory.expects_tool` couples a case to the tool's code identifier (`agent/tools.py`). Rejected as YAGNI: (a) a stable capability label on each `Tool`; (b) behavioral-effect assertions (can't cover info-only tools like `list_sources`). With 4 tools the name↔capability map is ~1:1. Principle: this binds tests to *implementation* not a *stable interface* — fine while names are stable. Revisit when tool names churn (most likely A2 native tool-calling); loader should validate `expects_tool` against the live registry so a rename fails loudly.
- **DD-026** (2026-06-15) — **Stronger embedder (MiniLM-L6 → mpnet-base-v2) — NO-OP, reverted.** Swapped the dense embedder 384→768-dim (same sentence-transformers family, both symmetric). Result: nothing moved — recall@5 .950→.950, MRR .975→.975, correctness **.773→.775** (noise). Reverted (mpnet ~5× the CPU cost for zero gain). Mechanism: at hybrid+cross-encoder the **dense embedder is masked** — BM25 + the reranker recover the same top-k regardless. The binding constraint is synthesis, not dense recall (saturated at .95). Lesson: upgrading a component a *downstream* stage already compensates for buys nothing — measure at the full pipeline.
- **DD-025** (2026-06-14) — **Role-tiered agent: separate `controller` and `generator` models.** The loop used one model for both routing (~5×/Q) and the final answer (1×/Q). Split into `llm.roles.controller`/`generator` (controller defaults to generator when unset, so the champion is unchanged). Motivation: **model tiering** — the DD-024 audit split failures 4 synthesis (generator) vs 4 coverage (retrieval), motivating a pro-*generator* A/B while the controller stays cheap. Cost instrumentation also split by role; the meter shows the controller is the larger spend (~5 calls/Q vs 1). Wiring shipped; the pro-generator A/B is pending.
- **DD-024** (2026-06-14) — **Per-run token-cost instrumentation (Module 5 pulled early).** Fork resolved: **Option A (widen the return)** not a hidden meter — `complete()` returns `Completion(text, usage)`, so cost is explicit and threads honestly through retries/fallback. `Usage{calls, prompt_tokens, completion_tokens}` rolls up per-call→per-question→per-run. **Tokens not dollars** (provider-neutral, near-zero variance at temp 0). Two buckets kept **SEPARATE**: `generator` (production cost) vs `judge` (instrument cost, no production counterpart) — never summed. Records calls/Q (cost of agency: naive=1, agentic≈6). Pure instrumentation, no eval gate.
- **DD-023** (2026-06-14) — **Module 3 context-selection A/Bs — all three LOST; the plain arrival-order budget trim is champion.** Vs the agentic champion (.800/.975): **(a) controller self-curation** (emit a `keep` list) LOST .800→.750, cite-hallucinations 0→3 — snippet pruning over-prunes (kept 1-of-9), a silent confident miss; **(b) round-robin-by-source** LOST .800→.725, faith→1.000 — fairness kills wrong answers but caps multi-part completeness, and fights parent-expansion; **(c) remove the budget** (16000→0) LOST .725, faith 1.000 — extra evidence *diluted* answers. Reverted to 16000. Reframe: the 16k trim (originally a Groq 6K-token survival hack) is now incidentally a **quality filter** — arrival order keeps early on-topic chunks. Reinforces DD-019: score is comparable *within* a source, not *across*.
- **DD-022** (2026-06-14) — **Agentic loop (Module 2) — A/B WON, default ON.** The answer path can be a hand-rolled **ReAct** loop (`agent/loop.py`): a controller reads a router-view of the scratchpad and emits one JSON action — `search(query)` or `finish` — bounded by `max_rounds` with oscillation/budget stops; the final answer is char-budgeted. Matched A/B: correctness **.750→.800**, faith **.944→.975**, **false-abstentions 4→0** — the loop *retries* where the naive generator gave up, and the gains came in grounded. Cost: one new INCORRECT (q26 — later found a **coverage** gap, not synthesis), ~3–4× latency. Direction is structural, magnitude within noise. Hand-rolled deliberately (no LangGraph) to learn what it abstracts.
- **DD-021** (2026-06-14) — **Gemini added as primary generator; router goes multi-tier (supersedes DD-004's Groq-only).** `GeminiProvider` (google-genai) as a second tier; `provider_order: [gemini, groq]` with per-role `{provider, model}` resolution + automatic fallback. **Generator = `gemini-2.5-flash-lite`** — this unblocked Module 2: Groq's free tier has a **6K-tokens/request wall** that 413'd the agent's scratchpad, while Gemini gives ~1s/call + ~1M context. **Judge = `gemini-2.5-pro`** (same family, so self-eval bias cancels in an A/B). Gemini handling: thinking disabled on flash (else eats `max_output_tokens`), capped on pro; `system_instruction`; assistant→`"model"`; backoff retry. Embeddings stay local.
- **DD-020** (2026-06-14) — **Parent-child expansion (small-to-big) — WON, adopted.** New retrieval stage 3 (`ParentExpansionRetriever`): after reranking, expand each top_k child into its ±`window` contiguous same-source neighbours, merged into one overlap-trimmed parent. Reuses the chunk store (no second-level chunking). Targets completeness partials (split tables/lists) by restoring local context **without** cross-topic distractors — the win a bigger top_k couldn't get. A/B (window=1): correctness **0.690→0.759**, reproduced ×2; recall unchanged. Default ON. Limits: same-source only (cross-*document* completeness unaffected); parents larger (~3k vs ~800 chars); window=2 untried.
- **DD-019** (2026-06-14) — **Reranker relevance gate A/B — LOST, removed.** Added a *relative* gate (`rerank.score_margin`: keep only hits within N logits of the top, may return <top_k). Relative because cross-encoder logits are uncalibrated. margin=4 lost: recall@5 1.000→0.966, correctness **0.690→0.655** — it cut a distractor (INCORRECT 1→0) but the same cut pruned a needed multi-hop chunk (+1 false abstention). Insight: a 2nd-hop chunk is *legitimately* lower-relevance (it answers the other sub-question), so it's indistinguishable from a distractor by score — **relevance ≠ answerhood**. No sweet-spot for this corpus. Experiments now in `docs/EXPERIMENTS.md`.
- **DD-017** (2026-06-14) — **Recursive chunking A/B — recursive LOST, kept fixed.** Format-agnostic recursive splitter (`recursive_chunk`, separator hierarchy, hand-rolled) vs fixed-size, generator held constant. Both meters regressed: recall@5 1.000→0.862, multi_hop@5 1.000→0.333; correctness **0.724→0.655**, +3 false abstentions. Cause: at the same `chunk_size=800` recursive breaks before filling → smaller chunks (304 vs 262) → multi-hop docs spread thinner, lose the top-5. Lessons: (1) the "obviously better" technique lost; (2) **strategy and `chunk_size` are coupled**; (3) the real completeness lever is parent-child, not recursive. A depth-10 probe confirmed coverage not ordering (multi_hop recall@10=1.000), but raising top_k to 8 didn't rescue end-to-end (distractors turned corrects into partials). Champion stays fixed @ top_k=5. Code kept off.
- **DD-018** (2026-06-14) — **Self-describing eval records.** Every run JSON embeds a `config` block (`retrieval_config_snapshot()` in `evals/runs.py`): mode, rerank + model, chunk strategy/size, top_k, hybrid params, embedding — plus generator/judge model for correctness. Reflects the **actual** mode used (so `--mode/--rerank` overrides are recorded faithfully). Motivation: a run must be reproducible from the file alone once many A/B runs accumulate.
- **DD-016** (2026-06-14) — **Ungraded ≠ incorrect** (eval integrity). `parse_verdict` previously fell through to `INCORRECT` on empty/off-format judge output (falsely sank q13). Fixed: unparseable → `UNGRADED`; `judge_correctness` re-asks up to 3× (most empties are transient); `report()` lists ungraded separately and **excludes them from the denominator** (`graded = answerable − ungraded`). Principle: a measurement you couldn't take is *missing data*, not a *failing result*.
- **DD-015** (2026-06-13) — **Completeness rule in the answer prompt** (`prompts/answer_with_citations.md`). The dominant post-rerank failure was PARTIAL (multi-part questions dropping facts). Added "answer COMPLETELY — every relevant item/step the CONTEXT provides; state definitive facts definitively," reconciled with concision (completeness = all relevant facts *from context*, not padding). A/B (rerank ON): **0.655→0.724, CORRECT 19→21, PARTIAL 9→6**. Caveat: one new INCORRECT was an empty-judge artifact (→ motivated DD-016).
- **DD-014** (2026-06-13) — **Cross-encoder reranking** — stage 2 of two-stage retrieval (`rag/rerank.py`). A cheap-and-wide first stage (bi-encoder/BM25) recalls a candidate pool, then an expensive **cross-encoder** re-scores each (query, chunk) pair jointly and keeps top_k — targeting "right doc, wrong chunk" misses. Model `ms-marco-MiniLM-L-6-v2` (local CPU). A/B won every cutoff: **recall@1 0.724→0.759, @3 0.793→0.931, @5 0.897→1.000, MRR 0.903→0.948**. Default ON. Trade: latency for precision; recall@5 now saturated, so @1/MRR + the answer eval are the discriminators.
- **DD-013** (2026-06-13) — **Role-aware LLM models** (generator vs judge). `llm.roles` maps a role to a model override. Generator = `llama-3.3-70b-versatile`, judge = `openai/gpt-oss-120b`. Two wins: (1) **separate Groq daily-token buckets** — 70b's TPD is tightest (100K vs gpt-oss-120b's 200K), so moving judging off it ~2×'s runs/day; (2) a **different-family judge removes self-eval bias** (DD-011). Principle: under per-model quota, the TPD ceiling *is* your iterations/day — spend the strong model only where the answer is born.
- **DD-012** (2026-06-13) — **Harness observability + LLM resilience.** Logging: `configure_run_logging(category)` writes a per-run file under `logs/<category>/` (gitignored) at DEBUG + a clean console handler; noisy libs quieted; completions log tokens+latency. Retry: rely on the Groq SDK's built-in backoff (429/5xx/timeout, honors Retry-After) via `max_retries=5`/`timeout=30` rather than hand-rolling. SDK retries the same provider; the router falls through to the next provider only after retries are exhausted.
- **DD-011** (2026-06-13) — **Answer-correctness eval** — rung 2 (`evals/answer_correctness.py`). Per question: a deterministic abstention check + an **LLM-as-judge** verdict (CORRECT/PARTIAL/INCORRECT) vs the verified `expected_answer`. Ground truth re-verified 32/32 by a fresh-context subagent. **Baseline: 19/29=0.655, abstention 3/3.** Failures cross-validate retrieval (false-abstentions = retrieval gaps; q22 hallucination motivates a faithfulness judge). Caveats: judge = generator model (self-eval bias), non-deterministic.
- **DD-010** (2026-06-13) — **Naive RAG answer pipeline** (`rag/answer.py`): hybrid-retrieve top_k → stuff source-labeled chunks into a versioned prompt → Groq generates a grounded, cited answer; abstains with exactly "Not enough information." Not agentic yet. **Key finding:** document-level recall@k overstates answerability — q01's doc is "retrieved" but the fact-bearing chunk ranks below top-5, so it correctly abstains. Motivates the answer-quality eval + chunk-level work. Adds groq + python-dotenv.
- **DD-009** (2026-06-13) — **Hybrid retrieval** (dense + **BM25**, fused by **RRF**, rrf_k=60, candidate_k=20) behind `retrieval.mode`, made default. Beats dense across the board: **recall@1 0.621→0.724, @3 0.759→0.793, @5 0.862→0.897, MRR 0.843→0.903**; BM25's keyword match fixes dense's findability misses. BM25 via the **rank_bm25** library (trusted lib + comments over hand-roll); sparse index built in-memory each run.
- **DD-008** (2026-06-13) — **Eval set hardened to v2:** added q13–q32 (29 answerable + 3 abstention), built by a fresh-context subagent verifying every `expected_sources`. recall@5 fell from a saturated **1.000 → 0.862** (gives headroom). New baseline: **recall@1=0.621, @3=0.759, @5=0.862, MRR=0.843**. Doc-verified failures now exist (q16 findability, q22/q26/q29 multi-hop). Supersedes DD-005's v1.
- **DD-007** (2026-06-13) — **Retrieval-recall eval** (`src/agentic_rag/evals/`): scores `seed.yaml`, no LLM. Reports recall@**{1,3,5}** + **MRR** (not just recall@5, which saturates at 1.0 on the 11-doc corpus). Scores only questions with `expected_sources` (abstention deferred to the answer-layer eval). Persists JSON to `eval_runs/` (gitignored). **Baseline: recall@1=0.667, @3=0.889, @5=1.000, MRR=0.889.**
- **DD-006** (2026-06-13) — **Naive ingestion pipeline** (`src/agentic_rag/rag/`): per-doc discover→chunk→embed→store. Idempotency via a **content-hash tracker** (sha256 of bytes, not mtime/size — avoids git-checkout false re-embeds and size-preserving missed edits) with full new/changed/deleted re-indexing. Store = **ChromaDB** (persistent, cosine HNSW); embeddings from local `all-MiniLM-L6-v2`. Chunking = fixed-size char windows (800/100). Adds pyyaml, sentence-transformers, chromadb.
- **DD-005** (2026-06-13) — Seed corpus = curated **11-doc** subset of `DocumentationRetrievalMCPServer/docs` (frozen into `corpus/`, not referenced live), chosen for cross-document multi-hop + an Azure-vs-ChromaDB distractor tension. Seed eval `seed.yaml` v1 = 12 Qs (9 answerable + 3 abstention); schema adds `match` (any/all) and `should_abstain`.
- **DD-004** (2026-06-13) — **Groq-only** for the LLM (`llama-3.3-70b-versatile`); fast LPU inference suits the eval loop. Embeddings **stay local** (`all-MiniLM-L6-v2`) — Groq has no embeddings endpoint. Layer stays router-shaped. Supersedes DD-003.
- **DD-003** (2026-06-11) — Gemini-only for now (`gemini-2.5-flash`); embeddings stay local. Router-shaped. Supersedes "Claude as primary."
- **DD-002** (2026-06-11) — Installable `src/` package via `pyproject.toml`; deps single-sourced there (no requirements.txt); `config/`/`prompts/`/`corpus/`/`evals/` versioned.
- **DD-001** (2026-06-11) — Evals are built early, alongside the naive baseline (not deferred); retrieval scored separately from answers.
